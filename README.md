# OStim Together

Current development version: **0.37.6**.

OStim Together synchronizes OStim Standalone scenes between Skyrim Together Reborn players. The `dev` branch uses **STRPluginMessagingAPI only**; there is no UDP fallback.

The root `VERSION` file is the single source of truth for CMake, DLL startup logs and archive names. Small fixes increment the patch number; larger feature/architecture work increments the minor number and resets the patch number.

## Current status

`main` currently contains the v0.37.5 stable checkpoint. `dev` contains the v0.37.6 OCum 3D diagnostic build.

### Core synchronization

OStim Together currently provides:

- player-to-player OStim scene start synchronization;
- player + NPC scene mirroring without forcing multiplayer-only alignment paths;
- exact OStim 7.5 furniture synchronization through Threads ABI v3;
- OStim 7.4c furniture fallback;
- wall-scene startup handling;
- shared native OStim NODE / SPEED / STOP controls;
- participant-authored OStim alignment synchronization;
- clock-calibrated free-standing scene phase replay;
- bounded mirror-self post-animation position correction;
- remote-proxy logical-origin correction for shared free scenes;
- equipment/outfit protection during scenes;
- safe orphan proxy-only OStim thread cleanup;
- targeted multiplayer consent / Add Actor gating;
- optional PPA runtime target synchronization;
- optional OCum Ascended RaceMenu overlay synchronization.

## OCum Ascended support

### Supported

OCum RaceMenu `CumOverlays` are synchronized between the true local player and the corresponding remote Skyrim Together proxy.

OStim Together keeps the true local PlayerCharacter fully owned by OCum/RaceMenu and mirrors the resulting overlay state read-only. The supported path includes the RaceMenu texture/decal properties and the live visibility metadata used by the remote proxy overlay bridge.

### OCum 3D meshes — investigation in v0.37.6

OCum uses the OStim equip-object types:

```text
ocumvagmesh
ocumanmesh
```

for its vaginal and anal 3D effects.

v0.37.4 proved that OStim Together could successfully transport an explicit remote mesh state, resolve the STR proxy, call `OActor.EquipObject(...)`, and read `OActor.IsObjectEquipped(...) == true` afterwards even when the mesh was not visible.

v0.37.5 therefore disabled OStim Together's explicit network synchronization of these two mesh objects while leaving local OCum behavior untouched.

Subsequent testing showed that OCum Ascended can independently create the 3D object on each client's local mirrored OStim scene. In particular, OCum's local `Creampie Chance` / `Analpie Chance` rolls can produce different results on the two clients, while a 100% setting can make the same 3D effect appear independently on both clients without any `ADDONOBJ` traffic from OStim Together.

v0.37.6 is therefore a **read-only diagnostic build**. It does not re-enable 3D mesh networking. Instead, while an OStim thread is active it records every 250 ms for every scene actor, including dynamic STR proxies:

- actor FormID and name;
- whether the actor is the true local PlayerCharacter or a dynamic scene actor/proxy;
- OCum backing-armor worn state for the vaginal and anal mesh forms;
- `OActor.IsObjectEquipped(actor, "ocumvagmesh")`;
- `OActor.IsObjectEquipped(actor, "ocumanmesh")`.

The diagnostic lines are written directly to `OStimTogether.log` as:

```text
OSTNET OCUM 3D DIAG ...
```

This allows us to determine whether a failed visual case is caused by a local OCum chance decision, an already-equipped but invisible OStim object, or another proxy-specific state issue.

No `EquipObject`, `UnequipObject`, or 3D mesh network packet is generated by this diagnostic path.

## Compatibility

Validated OStim runtime layouts:

- OStim 7.4c — `7.4.0.3`;
- OStim 7.5b — `7.5.0.2`.

The free-scene phase/alignment specialization targets the validated OStim 7.5b Threads API v3 path. Furniture and wall handling retain their dedicated paths.

The mandatory Add Actor gate `OSKSE.pex` compatibility patch is based on the validated OStim 7.5b interface and must win its file conflict against OStim's original script.

For multiplayer testing and release use, both Skyrim Together clients should run the same OStim Together version and compatible OStim/OCum/PPA versions.

## Optional integrations

### OCum Ascended

The FOMOD option synchronizes supported OCum RaceMenu overlays. In v0.37.6, OCum's 3D vaginal/anal equip objects remain excluded from OStim Together network traffic while their local state is observed read-only for diagnostics.

### PPA — Procedural Penis Animations

The optional PPA integration synchronizes runtime penetration target information between scene participants. If the PPA runtime is missing or unsupported, OStim Together disables the integration safely.

## Build

v0.37.6 changes only the native DLL and metadata relative to v0.37.5; `OStimTogetherOCum.psc` is unchanged. If your optional OCum PEX was already compiled for v0.37.5, no Papyrus recompilation is required for this diagnostic build.

Build the FOMOD with:

```powershell
$env:VCPKG_ROOT="C:\dev\vcpkg"
.\build-fomod.ps1
```

Expected output:

```text
dist\OStimTogether-v0.37.6-FOMOD.zip
```

FOMOD layout:

- `00 Core` — required DLL/INI plus mandatory Add Actor consent scripts;
- `10 OCum Ascended` — optional supported OCum RaceMenu overlay integration;
- `20 Procedural Penis Animations` — optional PPA synchronization.
